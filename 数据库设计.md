# Equipment_Management
下面给出的是**《设备管理系统数据库设计说明书（Database Design Specification）》**的完整目录和设计内容框架。这份设计与前面的《SRS》完全对应，采用 **MySQL 8.0 + InnoDB + utf8mb4**，共 **18 张业务数据表**，符合三级范式（3NF），满足后续 Spring Boot + MyBatis Plus 开发。

# 第一章 数据库总体设计

## 1.1 设计目标

设备管理系统数据库用于支撑设备全生命周期管理，实现设备档案、生命周期、维修管理、项目管理、附件管理、权限管理及日志审计等业务。

设计原则：

* 第三范式（3NF）
* 高内聚、低耦合
* 主外键完整性
* 唯一性约束
* 可扩展性
* 高性能索引设计
* 逻辑删除

# 第七章 数据完整性约束

数据库应满足以下约束：

| 约束项  | 说明                                                                            |
| ---- | ----------------------------------------------------------------------------- |
| 主键约束 | 所有业务表使用 `BIGINT` 自增或雪花算法 ID                                                   |
| 外键约束 | 建议逻辑关联，生产环境可根据性能需要不启用物理外键                                                     |
| 唯一约束 | 设备编号、SN号、业务IP、管理IP、用户名、项目编码均唯一                                                |
| 非空约束 | 关键业务字段（设备编号、设备名称、状态等）不能为空                                                     |
| 默认值  | 状态、创建时间、逻辑删除标志等设置合理默认值                                                        |
| 逻辑删除 | 使用 `deleted` 字段标识删除状态，不执行物理删除                                                 |
| 审计字段 | 每张业务表建议包含 `create_by`、`create_time`、`update_by`、`update_time`、`deleted` 等统一字段 |

# 第九章 数据库版本管理

建议使用数据库版本管理工具统一维护数据库结构。

推荐方案：

* **Flyway**（推荐，与 Spring Boot 集成简单）
* **Liquibase**（适用于复杂版本管理）

数据库脚本建议按以下目录组织：

```text
sql/
├── V1.0.0__init_schema.sql      # 创建数据库及18张表
├── V1.0.1__init_dict.sql        # 初始化字典数据
├── V1.0.2__init_admin.sql       # 初始化管理员账号
├── V1.1.0__add_statistics.sql   # 后续版本新增统计相关结构
└── V2.0.0__feature_upgrade.sql  # 二期功能升级
```

## 数据库设计总结

本数据库设计以 **device（设备主表）** 为核心，通过 **18 张业务表**覆盖了设备档案、配置、IP、项目、维修、附件、生命周期、权限管理及日志审计等全部业务场景。整体设计符合第三范式，支持设备全生命周期管理，并预留了良好的扩展能力，能够满足当前项目需求及未来版本升级。
